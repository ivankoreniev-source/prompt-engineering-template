You need to create a complete full-stack web application for creating, publishing, taking, and evaluating tests called QuizCraft.

The project consists of a FastAPI (Python) backend and a React + TypeScript frontend, designed with a clean, layered architecture and file-based persistence.

Do not start coding immediately. First understand the full system specifications, data models, workflows, and technical constraints below, then implement the project step by step.

============================================================
# 1. PROJECT SPECIFICATION & CORE CONCEPT
============================================================

QuizCraft is an interactive web platform where users can:

* Register, log in, manage their profile, and securely change passwords;
* Create custom tests with three question types (Single Choice, Multiple Choice, True/False);
* Configure answer options, designated correct answers, and author explanations;
* Edit, update, publish, unpublish, and delete their own tests;
* Browse a public catalog of published tests with real-time keyword search, category filtering, and difficulty filters;
* Take tests through a distraction-free, step-by-step test-taking interface;
* Receive instant, automated evaluation with score calculations (points, percentage, pass/fail status);
* Inspect a question-by-question breakdown showing user selections, correct answers, and explanations;
* Track test-taking history and performance analytics in "My Results" and authored tests in "My Tests".

The application must be simple, modern, responsive, accessible, and production-grade.

============================================================
# 2. USER ROLES & PERMISSIONS
============================================================

The application uses unified user accounts:

## Registered User
Every registered user has full capabilities:
* Browse published tests in the catalog without restriction;
* Take tests and record personal attempt results;
* View their personal history of test submissions;
* Create, manage, publish, and delete their own tests;
* Update personal profile information (email, bio) and change account password.

## Ownership & Isolation Rules
* Only the test author/creator can edit, update, publish, unpublish, or delete their test.
* Draft tests are strictly private and visible only to their author.
* Other users cannot take draft tests.
* Results are private to the user who took the test (and the system).
* Users cannot modify or delete tests authored by other users.

# 4. TECHNICAL ARCHITECTURE & STACK
============================================================

## Backend Architecture (FastAPI + Python 3.12+)
* **Layered Design**:
  - `app/models/` — Pydantic v2 schemas for request validation, domain entities, and response DTOs;
  - `app/types/` — Shared enums and type aliases;
  - `app/repositories/` — File-based data access layer reading/writing JSON stores with atomic writes;
  - `app/services/` — Business logic, authentication hashing, validation, scoring evaluation;
  - `app/routers/` — FastAPI endpoint controllers grouped by domain (`auth.py`, `tests.py`, `results.py`);
  - `app/dependencies.py` — Dependency injection providers for services, repositories, and `get_current_user`.
* **Data Storage**:
  - Central JSON stores located in `backend/data/`: `users.json`, `tests.json`, `results.json`, `sessions.json`.
  - Storage is file-based (one JSON file per entity containing an array of records).
* **Security & Auth**:
  - Password hashing: `hashlib.pbkdf2_hmac` with `sha256`, 100,000 iterations, and a unique 16-byte cryptographically secure salt.
  - Session tokens: Cryptographically secure URL-safe bearer tokens stored in `backend/data/sessions.json`.
  - CORS middleware supporting local development (`http://localhost:5174`, `http://127.0.0.1:5174`) and custom `CORS_ORIGINS`.

## Frontend Architecture (React + TypeScript + Vite)
* **Framework**: React 19 + TypeScript.
* **Styling**: Tailwind CSS v4 + `shadcn/ui` components (Button, Input, Card, Dialog, Badge, Toast, Tabs).
* **State Management**: Redux Toolkit:
  - RTK Query APIs: `baseApi.ts`, `authApi.ts`, `testsApi.ts`, `resultsApi.ts` with automated tag invalidation (`User`, `Test`, `Result`).
  - UI State Slices: `authSlice.ts` (session & user token), `uiSlice.ts` (notifications), `navigationSlice.ts` (active page routing).
* **Network & API Client**:
  - Base URL resolved dynamically via `src/lib/config.ts` (defaults to `http://localhost:8001/api`, overridable via `VITE_API_BASE_URL`).

## Documentation Structure
* Single consolidated documentation folder per feature under `docs/<feature>/`:
  - `docs/auth/`: `business-requirements.md`, `architecture.md`, `test-cases.md`
  - `docs/tests/`: `business-requirements.md`, `architecture.md`, `test-cases.md`
  - `docs/test-taking/`: `business-requirements.md`, `architecture.md`, `test-cases.md`
  - `docs/results/`: `business-requirements.md`, `architecture.md`, `test-cases.md`

## Automation & Startup
* `start.bat`: One-click root startup script for Windows that verifies Node/Python, installs dependencies if needed, launches backend and frontend in separate console windows, and opens `http://localhost:5174`.

# 6. CORE API ENDPOINTS
============================================================

## Authentication (`/api/auth`)
* `POST /api/auth/register` — Register new user, returns bearer token + user profile.
* `POST /api/auth/login` — Login by username or email, returns bearer token + user profile.
* `POST /api/auth/logout` — Invalidate token session.
* `GET  /api/auth/me` — Retrieve current authenticated user profile.
* `PATCH /api/auth/profile` — Update email/bio and change password.

## Tests Management (`/api/tests`)
* `GET    /api/tests` — List published tests (supports `?search=`, `?category=`, `?difficulty=`).
* `POST   /api/tests` — Create draft test (auth required).
* `GET    /api/tests/my` — List all authored tests for current user (draft + published).
* `GET    /api/tests/{id}` — Get test details (creator gets full test; others get published summary).
* `PUT    /api/tests/{id}` — Update authored test (creator only).
* `DELETE /api/tests/{id}` — Delete authored test (creator only).
* `POST   /api/tests/{id}/publish` — Validate questions and publish test (creator only).
* `POST   /api/tests/{id}/unpublish` — Revert test to draft (creator only).
* `GET    /api/tests/{id}/take` — Retrieve test with sanitized questions (NO answer keys).
* `POST   /api/tests/{id}/submit` — Submit answers, grade attempt, persist result, return evaluation report.

## Results & Analytics (`/api/results`)
* `GET /api/results/my` — List all test attempts for the current user.
* `GET /api/results/{id}` — Get detailed result breakdown with answers, correctness, and explanations.

# 7. EVALUATION & SCORING RULES
============================================================

1. **Single Choice**:
   - The user selects exactly 1 option ID.
   - Point awarded (1/1) if the selected option ID matches `correct_answers[0]`.

2. **Multiple Choice**:
   - The user selects 1 or more option IDs.
   - Point awarded (1/1) if and only if the set of selected option IDs exactly matches the set of `correct_answers`.
   - Partial credit is not awarded unless explicitly configured.

3. **True / False**:
   - The user selects either True or False.
   - Point awarded (1/1) if the selection matches `correct_answers[0]`.

4. **Overall Score Calculation**:
   - `total_questions` = total count of questions in the test.
   - `score` = count of correctly answered questions.
   - `percentage` = `round((score / total_questions) * 100.0, 1)`.
   - `passed` = `percentage >= 60.0`.

============================================================
# 8. SECURITY & DATA PRIVACY REQUIREMENTS
============================================================

1. **Answer Key Protection**:
   - The taking endpoint `GET /api/tests/{id}/take` MUST sanitize every question before returning it to the client. Under no circumstances should `correct_answers` or `explanation` be sent over the network during test taking.
2. **Access Control**:
   - Tests can only be modified or deleted by their original creator (`creator_id == current_user.id`).
   - Draft tests cannot be accessed via the `/take` endpoint.
3. **Password Security**:
   - Passwords must be hashed with PBKDF2-HMAC-SHA256 and salted. Never store plain text passwords.
4. **Data Isolation**:
   - User results and account details are isolated. All data stores in `backend/data/*.json` must be kept clean, valid JSON arrays.
